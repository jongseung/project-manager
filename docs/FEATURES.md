## 사용 맥락 (Context)

이 앱의 사용자(Parker)는 두 가지 영역을 하나의 도구로 관리한다:

| 영역 | 예시 프로젝트 | 특징 |
|------|-------------|------|
| **업무** | CMP 장비 모니터링 대시보드 개선, 공정 데이터 파이프라인, 내부 툴 개발, 월간 보고 | 마감일 엄격, 팀원 협업, 반복 루틴 많음 |
| **사이드** | 바이낸스 트레이딩봇, 발자취 앱, 홈서버 관리, 블로그/콘텐츠 | 마감일 유연, 대부분 혼자, 장기 방치 후 재개 빈번 |

→ 이 두 영역을 **Workspace** 단위로 분리하되, **대시보드에서 통합 조회**할 수 있어야 한다.

## 1. 반복 태스크 / 루틴 시스템

### 1.1 개요

매일·매주·매월 반복되는 작업을 템플릿으로 등록하면, 시스템이 자동으로 태스크를 생성해준다.

### 1.2 실제 사용 시나리오

```
[업무 루틴]
- 매일 오전: CMP 장비 가동률 체크 → 이상 있으면 리포트
- 매주 월요일: 주간 업무 보고 작성
- 매주 수요일: 팀 미팅 안건 준비
- 매월 1일: 월간 KPI 정리 및 보고
- 매분기: 장비 PM(예방정비) 스케줄 리뷰

[사이드 루틴]
- 매일 장마감 후: 트레이딩봇 수익률 확인 & 로그 리뷰
- 매주 일요일: 사이드 프로젝트 주간 회고 (뭘 했는지, 다음 주 계획)
- 매월 15일: 홈서버 보안 업데이트 & 백업 확인
```

#### 자동 생성된 태스크 표시

- 칸반/리스트에서 반복 태스크는 **🔄 아이콘** + 연한 배경색으로 구분
- 태스크 카드에 "반복 태스크 · 매주 월요일" 서브텍스트 표시
- 클릭 시 상세 모달에 "원본 템플릿 보기" 링크

#### 완료 통계

- 루틴 상세 페이지에서 "최근 30일 완료율" 표시
- 예: "장비 가동률 체크 — 22/22일 완료 (100%) 🔥"
- streak(연속 완료일수) 카운터

#### Cron 동작 흐름

```
[Vercel Cron: 매 시간 정각]
     │
     ▼
GET /api/cron/recurring
     │
     ├─ DB에서 nextRunAt <= now && isActive 인 템플릿 조회
     │
     ├─ 각 템플릿마다:
     │   ├─ Task 생성 (title, description, priority, labels, subtasks 복사)
     │   ├─ dueDate = now + template.dueDateOffset (설정된 경우)
     │   ├─ assigneeId = template.defaultAssigneeId
     │   ├─ boardColumn = "todo"
     │   ├─ recurringId = template.id (추적용)
     │   │
     │   ├─ nextRunAt 재계산
     │   │   ├─ DAILY: +interval일
     │   │   ├─ WEEKLY: 다음 daysOfWeek 중 가장 빠른 날
     │   │   ├─ MONTHLY: 다음 달 dayOfMonth
     │   │   └─ CUSTOM: interval 기반 계산
     │   │
     │   └─ lastRunAt = now
     │
     └─ 로그 기록 (생성된 태스크 수, 에러 여부)
```

#### 스킵 & 연기 기능

- 오늘의 반복 태스크를 "오늘은 스킵" 가능 (skip_count 기록)
- "내일로 연기" → dueDate만 +1일, 템플릿 주기는 그대로

## 2. 칸반보드

### 2.1 개요

태스크를 시각적으로 상태별 컬럼에 배치하고, 드래그앤드롭으로 상태를 변경한다.

### 2.2 실제 사용 시나리오

```
[업무 보드 - CMP 모니터링 프로젝트]
할 일 → 진행 중 → 리뷰 → 완료

[사이드 보드 - 트레이딩봇]
아이디어 → 백테스트 → 구현 중 → 라이브 테스트 → 운영 중

[사이드 보드 - 발자취 앱]
기획 → 디자인 → 개발 → 테스트 → 배포
```

#### 멀티 보드 뷰

- **프로젝트별 보드**: 프로젝트 선택 시 해당 프로젝트 태스크만 표시
- **전체 보드**: 워크스페이스 전체 태스크 (프로젝트 라벨로 구분)
- **"내 보드"**: 로그인 유저에게 배정된 태스크만 (프로젝트 무관)

#### 커스텀 컬럼

- 기본: `할 일 | 진행 중 | 리뷰 | 완료`
- 프로젝트별로 커스텀 가능 (예: 트레이딩봇은 `아이디어 | 백테스트 | 구현 | 라이브 | 운영`)
- 컬럼 설정: 이름, 색상, 매핑할 TaskStatus, WIP 제한(선택)

```
WIP 제한: "진행 중" 컬럼에 최대 3개
→ 3개 초과 시 컬럼 헤더 빨간색 경고
→ 드래그는 가능하지만 경고 표시
```

## 3. 캘린더 / 타임라인 뷰

### 3.1 개요

시간 축 기반으로 태스크와 루틴을 시각화. 두 가지 뷰를 제공한다:
- **캘린더 뷰**: 월/주/일 단위로 마감일 기반 태스크 배치
- **간트 차트**: 프로젝트/마일스톤의 기간 기반 타임라인

### 3.2 실제 사용 시나리오

```
[캘린더로 보고 싶은 것]
- 이번 주 마감인 업무 태스크들
- 반복 루틴이 어떤 날에 걸려있는지
- 사이드 프로젝트 마일스톤 기한
- "오늘 뭐 해야 하지?" → 일간 뷰

[간트 차트로 보고 싶은 것]
- CMP 모니터링 프로젝트 전체 타임라인 (3개월)
- 트레이딩봇 개발 진행률 (Phase별)
- 발자취 앱 마일스톤 (기획→개발→배포)
```

## 4. 대시보드 / 분석

### 4.1 개요

"지금 내 상태가 어떤지"를 한눈에 보여주는 화면. 개인 대시보드와 팀 대시보드를 모두 제공.

### 4.2 실제 사용 시나리오

```
[매일 아침 출근 시]
→ 대시보드 열어서 "오늘 할 일" 확인, 오버듀 체크

[주간 보고 작성 시]
→ 이번 주 완료 태스크 수, 진행률 차트 캡처

[회고 시]
→ 월간 완료율 추이, 어떤 프로젝트에 시간 많이 쓰는지

[사이드 프로젝트 리뷰 시]
→ 각 프로젝트별 진행률 한눈에 비교
```

## 부록: 구현 시 주의사항

### 반복 태스크
- Vercel Cron 무료 티어는 하루 1회. 더 자주 필요하면 Vercel Pro 또는 외부 cron (cron-job.org) 사용
- 타임존 처리 필수: 사용자 타임존 저장 후 nextRunAt 계산 시 반영
- 중복 생성 방지: lastRunAt과 비교하여 같은 주기에 2번 생성되지 않도록

### 칸반보드
- sortOrder는 정수 gap 방식 (1000, 2000, 3000...) → 중간 삽입 시 1500
- gap이 좁아지면 리밸런싱 (전체 재정렬)
- 낙관적 업데이트: 드래그 즉시 UI 반영, 백그라운드 API 호출

### 캘린더
- @fullcalendar는 번들 크기가 큼 → dynamic import 필수
- 수백 개 이벤트 시 성능: 현재 뷰 범위만 fetch (월간 뷰면 해당 월 ±1주)

### 대시보드
- 통계 쿼리 최적화: 복잡한 aggregation은 별도 API, 캐싱 (React Query staleTime 5분)
- 차트 데이터는 서버에서 가공해서 내려주기 (클라이언트에서 raw 데이터 처리 X)
