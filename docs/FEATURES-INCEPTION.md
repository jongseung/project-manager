# 🎯 FEATURES-INCEPTION.md — 프로젝트 기획 & KPI 추적 시스템

> 프로젝트를 "그냥 시작"하는 게 아니라,
> **목표 설정 → 브레인스토밍 → 스토리 도출 → 태스크 분해 → 실행 → KPI로 성과 측정**
> 이 전체 사이클이 하나의 흐름으로 연결되는 시스템.

---

## 1. 프로젝트 인셉션 (DEFINE)

### 프로젝트 생성 시 확장된 폼

기존 PLANNING.md의 Project 모델을 확장한다.
프로젝트 생성 시 "빠른 생성"과 "풀 기획" 두 가지 모드를 제공.

### 데이터 모델 확장

```prisma
// 기존 Project 모델에 추가

model Project {
  // ... 기존 필드 유지 ...

  // 인셉션 필드 추가
  summary         String?   // 한줄 요약
  problemStatement String?  // 왜 하는가
  definitionOfDone String?  // 성공 기준
  
  // 관계 추가
  objectives    Objective[]
  stories       Story[]
  brainstormNodes BrainstormNode[]
}

model Objective {
  id          String   @id @default(cuid())
  title       String                          // "이상 감지 시간 단축"
  description String?
  sortOrder   Int      @default(0)
  createdAt   DateTime @default(now())

  projectId   String
  project     Project    @relation(fields: [projectId], references: [id], onDelete: Cascade)
  keyResults  KeyResult[]
}

model KeyResult {
  id            String      @id @default(cuid())
  title         String                        // "감지→알림 5분 이내"
  metricName    String                        // "detection_time_minutes"
  metricUnit    String      @default("")      // "분", "%", "건", "점" 등
  currentValue  Float       @default(0)       // 현재값
  startValue    Float       @default(0)       // 시작값 (baseline)
  targetValue   Float                         // 목표값
  direction     Direction   @default(DECREASE) // 올라야 좋은지, 내려야 좋은지
  deadline      DateTime?
  sortOrder     Int         @default(0)
  createdAt     DateTime    @default(now())
  updatedAt     DateTime    @updatedAt

  objectiveId   String
  objective     Objective   @relation(fields: [objectiveId], references: [id], onDelete: Cascade)
  
  // KPI 이력
  snapshots     KRSnapshot[]
  
  // 이 KR에 기여하는 스토리/태스크 연결
  linkedStories StoryKRLink[]
}

enum Direction {
  INCREASE    // 높을수록 좋음 (완료율, 커버리지 등)
  DECREASE    // 낮을수록 좋음 (응답시간, 불량률 등)
  MAINTAIN    // 특정 범위 유지
}

model KRSnapshot {
  id          String   @id @default(cuid())
  value       Float
  note        String?                         // "v1 배포 후 측정"
  recordedAt  DateTime @default(now())

  keyResultId String
  keyResult   KeyResult @relation(fields: [keyResultId], references: [id], onDelete: Cascade)
}
```

### KPI 기록 방법

KPI 값은 **수동 입력** + **자동 계산** 두 가지 방식을 지원:

```
[수동 입력]
→ KPI 카드에서 "값 업데이트" 버튼
→ 새 값 + 메모 입력 (예: "v1.2 배포 후 측정")
→ KRSnapshot으로 이력 저장

[자동 계산] (Phase 5 확장)
→ 특정 KR은 태스크 데이터에서 자동 계산
→ 예: "태스크 완료율" = 완료 태스크 / 전체 태스크
→ 예: "평균 처리 시간" = avg(completedAt - createdAt)
```

## 3. 브레인스토밍 & 마인드맵 (EXPLORE)

### 개요

프로젝트 목표가 정해지면, **브레인스토밍 캔버스**에서 자유롭게 아이디어를 펼치고,
이를 구조화하여 스토리와 액션아이템으로 변환한다.

### 브레인스토밍 캔버스 화면

```
┌─ 브레인스토밍: CMP 모니터링 v2 ──── [마인드맵] [리스트] [카드] ──────┐
│                                                                     │
│                        ┌──────────────┐                             │
│                        │ CMP 모니터링  │                             │
│                        │     v2       │                             │
│                        └──────┬───────┘                             │
│                 ┌─────────────┼─────────────┐                       │
│                 │             │             │                       │
│          ┌──────▼─────┐ ┌────▼─────┐ ┌─────▼──────┐                │
│          │ 🔴 데이터   │ │ 🟢 알림   │ │ 🔵 대시보드 │                │
│          │    수집     │ │   시스템  │ │    개선    │                │
│          └──────┬─────┘ └────┬─────┘ └─────┬──────┘                │
│           ┌─────┼─────┐     │         ┌────┼────┐                   │
│           │     │     │     │         │    │    │                   │
│        ┌──▼─┐┌──▼─┐┌──▼─┐┌──▼──┐  ┌──▼─┐┌──▼─┐┌──▼─┐              │
│        │센서 ││DB  ││엣지 ││Slack││  │실시 ││차트 ││리포 │              │
│        │폴링 ││파이프││컴퓨 ││연동 ││  │간  ││개선 ││트  │              │
│        │최적 ││라인 ││팅  ││    ││  │상태 ││    ││자동 │              │
│        │화  ││    ││   ││    ││  │표시 ││    ││화  │              │
│        └────┘└────┘└────┘└─────┘  └────┘└────┘└────┘              │
│                                                                     │
│  ── 빠른 메모 ──                                                    │
│  💡 "엣지 컴퓨팅 도입하면 네트워크 지연 없앨 수 있을 듯"              │
│  💡 "김대리가 Grafana 연동 경험 있다고 했음"                          │
│  💡 "기존 MSSQL 데이터도 통합해야 함"                                │
│                                                                     │
│  [+ 노드 추가]  [+ 메모 추가]           [→ 스토리로 변환]            │
└─────────────────────────────────────────────────────────────────────┘
```

### 뷰 모드 3가지

| 모드 | 설명 | 적합한 상황 |
|------|------|------------|
| **마인드맵** | 트리 구조, 드래그로 연결/배치 | 아이디어 확산, 구조 잡기 |
| **리스트** | 계층형 불릿 리스트 (들여쓰기) | 빠른 입력, 텍스트 중심 |
| **카드** | 포스트잇 스타일 그리드 | 그룹핑, 우선순위 정렬 |

## 4. 스토리 & 액션아이템 분해 (PLAN)

### 개요

브레인스토밍에서 나온 아이디어를 **스토리**(사용자 관점 기능 단위)로 정리하고,
각 스토리를 **태스크 → 서브태스크**로 분해한다.

### 스토리 ↔ KR ↔ 태스크 관계

```
Objective (목표)
 └── Key Result (핵심 결과)
      └── Story (스토리) ← 브레인스토밍 노드에서 변환
           └── Task (태스크)
                └── Subtask (서브태스크)
```

model Story {
  id              String      @id @default(cuid())
  title           String                              // "데이터 수집 파이프라인 구축"
  asA             String?                             // "CMP 엔지니어"
  iWant           String?                             // "장비 센서 데이터가 실시간 수집"
  soThat          String?                             // "이상 발생 즉시 감지"
  storyPoints     Int?                                // 스토리 포인트 (피보나치)
  status          StoryStatus @default(BACKLOG)
  expectedImpact  String?                             // "감지 시간 -10분"

  updatedAt       DateTime    @updatedAt
  completedAt     DateTime?

  keyResultId String
  keyResult   KeyResult @relation(fields: [keyResultId], references: [id], onDelete: Cascade)

  @@unique([storyId, keyResultId])
}

## 8. 자동화 & 트리거

### 스토리 완료 시 KPI 리마인더

```
스토리의 모든 태스크가 DONE
  │
  ▼
Story.status = DONE, Story.completedAt = now()
  │
  ▼
연결된 KR이 있는가?
  │
  ├─ YES → Notification 생성:
  │         "📊 '데이터 수집 파이프라인' 스토리가 완료되었습니다.
  │          KR 1.1 (감지→알림 시간)의 현재 값을 업데이트해주세요.
  │          예상 영향: -10분
  │          [값 업데이트하기]"
  │
  └─ NO → 일반 완료 처리
```

### KPI 자동 계산 가능 항목

일부 KR은 태스크 데이터에서 자동 계산:

| KR | 자동 계산 방법 |
|----|---------------|
| 태스크 완료율 | (DONE tasks / total tasks) × 100 |
| 평균 태스크 처리 시간 | avg(completedAt - createdAt) |
| 주당 완료 태스크 수 | count(completedAt in this week) |
| 오버듀 비율 | (overdue tasks / total tasks) × 100 |

→ 이런 KR은 `autoCalculate: true` 플래그로 표시, 대시보드에서 실시간 반영.
